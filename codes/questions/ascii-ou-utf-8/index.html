ASCII ou UTF-8 : la différence

L'ASCII est un code de 128 caractères sur 7 bits, sans accents ; l'UTF-8 encode tous les caractères Unicode sur 1 à 4 octets, et reste identique à l'ASCII pour ces 128 premiers caractères.

Compatibles pour l'essentiel

L'UTF-8 a été conçu pour qu'un texte ASCII soit déjà un texte UTF-8 valide : les 128 premiers caractères gardent le même octet. Un fichier qui ne contient que des lettres sans accent, des chiffres et de la ponctuation courante est donc identique dans les deux encodages. La différence n'apparaît qu'avec les autres caractères.

Pourquoi un é devient « Ã© »

En UTF-8, é s'écrit avec deux octets, C3 A9. Si un logiciel lit ces octets avec une ancienne table occidentale (Latin-1 ou Windows-1252) au lieu de l'UTF-8, il voit deux caractères : C3 donne « Ã » et A9 donne « © ». D'où le fameux « Ã© » à la place du é, et « Ã§ » à la place du ç. Le texte n'est pas abîmé : il est simplement lu avec le mauvais encodage.

Lequel utiliser ?

Pour un texte en français, l'UTF-8 : c'est l'encodage du web, il gère les accents et tous les alphabets. L'ASCII reste une base utile à connaître, parce que ses 128 codes sont partout : dans les protocoles, dans les adresses, dans la table ASCII.

Voir la différence

Tapez « été » dans le convertisseur hexadécimal : vous obtenez C3 A9 74 C3 A9, cinq octets pour trois lettres. La table ASCII de ce site affiche aussi la fiche UTF-8 de tout caractère tapé dans sa recherche.

Questions fréquentes

L'ASCII contient-il les accents ?

Non. Ses 128 caractères ne comprennent aucune lettre accentuée ; il faut l'UTF-8 (ou une ancienne table étendue).

Un texte ASCII est-il aussi de l'UTF-8 ?

Oui. Les 128 caractères ASCII gardent le même octet en UTF-8.

Pourquoi vois-je « Ã© » au lieu de « é » ?

Le texte est en UTF-8 mais il est lu avec une ancienne table : les deux octets du é sont affichés comme deux caractères.
